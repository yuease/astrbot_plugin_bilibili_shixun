# B站拾讯

在 AstrBot 中直连 B 站，通过管理员私聊临时搜索、管理长期订阅、查询原文或按需生成简报。公开关键词视频搜索无需扫码；UP 主与自己的关注来源使用扫码账号。**不依赖 RSSHub，不需要额外服务或独立 Python 环境。**

当前为 v0.7.0，提供源码安装包，未部署。此次内部名称也已变更：请先停用旧插件，再全新安装，重新配置插件、扫码与启用人格中的九个新工具；按用户要求不提供旧数据迁移。当前元数据限定 AstrBot 4.29.1。完整检查范围见文末及验证记录。

## 登录

在 QQ 管理员私聊中发送：

- `/B站登录`：收到二维码图片，用 B 站 App 扫码并确认；机器人会通知结果。
- `/B站状态`：查看登录状态、账号 UID 和自动提醒设置。
- `/B站退出`：清除插件保存的凭据和通知绑定，停止自动重扫提醒；不会替你退出其他设备。

QQ 扫码流程参考 [dsh-bili-scroll](https://github.com/c1overzz/dsh-bili-scroll/blob/main/lib/login.mjs)，在插件中独立实现。二维码只保存在内存，不通过模型处理；凭据保存在运行 AstrBot 的服务器上，不在聊天、页面状态、报告中展示。

本版使用一份共享管理员档案、一个 B 站账号。登录和退出由完成绑定的管理员操作；其他管理员不会收到该账号的自动二维码。

确认登录失效后，默认向绑定的私聊发送一轮新二维码。定期检查与采集遇到明确未登录响应都会触发失效判定；网络超时、限流或风控不会被误判为过期。二维码本身过期后不连续自动重发，手动发送登录命令即可重新获取。

自动推送当前支持 **OneBot/aiocqhttp**。QQ 官方适配器可以手动获取二维码，但当前 AstrBot 的主动发送接口不能提供同样的自动提醒。未绑定私聊前不会向任意管理员广播二维码。

## 配置

将插件放入 `data/plugins/astrbot_plugin_bilibili_shixun`，由 AstrBot 按 `requirements.txt` 安装依赖。采集复用固定版本 `bilibili-api-python`；无需安装或运行参考项目。

插件配置有五项：

- `briefing_provider_id`：简报使用的 AstrBot 模型 ID，留空使用默认聊天模型。
- `model_timeout_seconds`：简报模型等待上限，默认 90 秒，范围 10–300。
- `dashboard_admins`：允许使用页面的 Dashboard 用户名，留空使用 `dashboard.username`。
- `bili_auto_relogin`：登录失效时自动私聊发送二维码，默认开启。
- `bili_check_interval_minutes`：登录检查间隔，默认 30 分钟，范围 5–1440。

聊天管理员由当前会话配置的 `admins_id` 决定。没有 Cookie 文本、来源服务器地址、worker_python 或独立模型密钥配置。

## 采集与使用

1. 临时搜索可直接在管理员私聊中说“去 B 站搜索天文视频，不要订阅”。使用 UP 或关注来源前先完成扫码。
2. 长期采集可让 Bot 增量添加关键词并启用关键词来源，或打开插件视图添加关键词、UP 主、启用“我的关注”。关注 UID 随扫码账号自动填写。
3. 设置兴趣、过滤规则和采集计划，再点击“刷新来源”。
4. 私聊提问查询已采集原文，或在页面生成简报。

关键词与投稿按最新发布读取一页，动态可在预算内分页。采集有请求次数、时间和候选数量限制，不保证取得全部历史。转发文字与原作者内容分开保留，图片仅展示，不识图或假设已经观看视频。

来源请求串行且设置间隔；B 站接口或库仍可能变化，真实可用性取决于接口、账号与网络。插件只注册读取内容所需的接口，不提供点赞、评论、发动态等操作。

## 聊天与简报

**聊天检索不额外调用筛选模型。** 当前注册九个工具：

- `bilibili_get_subscriptions_and_preferences`：查看与页面共用的长期关键词、兴趣、来源、过滤及采集设置，以及版本、最近变更和数据状态。
- `bilibili_update_subscriptions_and_preferences`：增量增删长期关键词、修改兴趣、开关关键词来源，不覆盖 UP 与关注订阅，不自动采集。
- `bilibili_undo_settings_change`：按变更编号撤销一次 Bot 或页面设置修改，校验版本并防止覆盖后续改动。
- `bilibili_search_videos_online`：免登录临时联网搜索 B 站视频，不自动写入长期订阅。
- `bilibili_search_saved_content`：统一查询入口，按来源、时间及可选关键词读取本地候选。
- `bilibili_read_content_detail`：读取正文、逐段归属、图片列表和已采集附件详情，不自动发送图片。
- `bilibili_get_source_status`：查看来源状态、采集时间、扫描停止原因。
- `bilibili_refresh_subscriptions`：开始刷新或查询刷新任务。
- `bilibili_send_content_images`：用户明确要求看图时，默认发送原图，也可明确选择预览缩图。

“今天关注的 UP 更新了什么”按来源和今天筛选，`terms` 可以省略；不要把“关注”“更新”当作正文关键词。指定主题时才传入关键词，多个词按 AND 匹配。`question` 仅供回显，执行条件由模型明确填写，不会由插件另行理解或筛选问题。来源不知道时先查看来源状态。

修改前 Bot 先读取 `version`，再按用户要求增删关键词或更新兴趣；长期关键词总数最多五个，删除全部关键词只关闭关键词来源。新增关键词默认保留当前来源开关，要开始长期关键词采集需明确开启。兴趣修改沿用已有学习目标及反馈记录。撤销只恢复目标变更涉及的字段，保留其他后续设置；同一字段后来被改过会拒绝撤销。请求回执跨重载保存，重复请求不重复修改。

Bot 和页面共用一份设置及版本。页面约每四秒检查更新：未编辑的当前表单自动载入，正在编辑的草稿保留并提示重新载入；旧版本提交会被拒绝。**订阅已保存、正在采集、已有结果分别报告**，保存不会自动刷新。若用户明确将临时关键词加入长期订阅，可转入尚未过期的缓存内容，回执会说明数量；这不表示又做了一次联网采集。

临时搜索每次匿名读取按最新发布排序的一页 20 个视频候选，可显式选择远端第 1–3 页，每条消息最多三次不同搜索。默认展示五条，单次最多十条；默认最多等待十秒，可设 0–20 秒。等待超时不取消任务，使用 `action=status` 和返回的 `search_id` 继续查看；status 不重复联网。来源接口等待上限二十秒，SDK 内部签名等 HTTP 请求数不假报为一次。失败、正在搜索、成功但无匹配分别返回；不调用额外模型判断主题相关性。

临时证据和任务结果保留 24 小时，每个账号范围最多保留 200 条临时证据；过期后需在新消息中重新搜索。同一消息相同搜索参数复用回执。后续可通过 `search_items` 的 `sources=[{kind:"temporary_keyword",key:"搜索词"}]` 读取保留结果、用 `get_item` 看详情；**这个来源选择器本身不会联网**。临时搜索不要求先创建永久档案，也不自动修改关键词或兴趣。

列表直接包含 `image_count`、`images_status`、`attachment_types`、`has_attachments`、`attachments_status`。寻找有图片的动态可用 `has_images=true`，不需要逐条打开详情，也不能仅凭 `image_dynamic` 判断有图。`image_count` 统计已采集的可发送内容图片，不含视频封面或投票选项图片；数量为 0、状态为 `unknown/partial` 时，不能断言原帖没有图片。`has_images=false` 只返回已确认无内容图片的记录。旧记录附件信息未知，重新刷新来源后才会补齐。

详情的 `attachments` 区分图片、投票、视频、专栏、音频、直播、预约、链接和未知类型；投票保留问题及选项文字，付费表情占位符转换成可读文字。缺失的投票选项在采集时按固定 SDK 接口补读，每批最多两份详情，每次最多三秒且计入来源总超时；按账号缓存一分钟。失败不丢弃整批动态，`details_status=unavailable` 表示补读失败，`partial` 表示信息缺失、预算未补读或文本达到限额。问题最多 500 字、选项最多 20 个且每项最多 300 字，不编造未获取内容。简报输入也包含这些附件信息。

列表只给精简摘要与来源，不重复正文证据。`total_matches` 只统计本地保留数据；`has_more` 表示列表还有下一页，单条摘要是否截断看 `snippet_truncated`，详情正文看 `body_truncated`，不再用一个 `truncated` 混合表示。详情保留 `attributions`，其中正文起止位置对应具体作者及原文链接。

所有查询时间按请求的 `timezone` 返回，默认 `Asia/Shanghai`；详情和来源状态也可以指定时区。转发条目分别提供转发时间、原文发布时间、原作者和转发者，不把今天转发的旧内容说成今天首发。工具输出用 `text_dynamic` 表示文字动态，`image_dynamic` 表示带图动态；存储仍兼容原有类型。

`coverage.completeness` 为 `unknown` 或 `incomplete`，不据条数猜测完整性。`scan` 记录页数、分页是否结束、观察到的最早/最新时间和停止原因；`ready` 仅表示接口采集成功。即使已读到接口分页末尾，也不保证 B 站完整返回了全部关注内容。`missing_publication_time_count` 只表示缺少发布时间的条数。

在管理员私聊中要求机器人“刷新一下来源”，会使用刷新工具。默认 `action=start`，联网采集全部已保存来源；`action=status` 只查询当前账号最近一次采集任务，不触发刷新。两种操作默认最多等待 10 秒，可用 `wait_seconds` 设置 0–20 秒；0 立即返回，等待超时也不取消后台采集。仍在运行时可继续用 status 有限等待，不需要 shell 或固定 sleep。需先保存有效来源；仅启用关键词来源时可匿名刷新，启用 UP 或关注来源则需扫码。不修改订阅，也不生成简报或调用额外模型。

刷新在后台执行：`operation_finished` 只表示任务已结束，失败的任务也会为 true；`operation_succeeded` 表示流程是否保存可用结果。数据范围另用 `data_completeness` 表达：明确触及上限或失败时为 `incomplete`，`data_complete=false`；无法确认时为 `unknown`，`data_complete=null`，不声称全集已取完。`warnings` 始终为数组，包含页数上限、请求/时间预算、分页异常和来源失败等实际限制。汇总给出总页数、来源条目数（跨来源未去重）、候选数及各来源停止原因。旧任务没有汇总时显示覆盖未知。完成后使用检索工具读取新内容，不主动向聊天推送完成通知。同一消息重复请求只执行一次；采集期间的新刷新请求复用现有任务，重复请求记录跨重载保留。

工具需要明确传入“今天”等时间条件。`search_items` 只查本地候选；刷新工具联网采集已保存来源；临时搜索工具联网搜索指定关键词的视频。每条消息最多八种不同工具请求，临时联网搜索另限三次。

查询通过 `requested_sources` 逐项报告所选来源：不存在、已停用、未采集、采集失败、失败后保留旧内容、快照早于查询时段、成功采集为空，以及正常可查。混合来源不会静默丢弃未满足的部分；部分范围不可用且没有命中时为 `partial_scope_no_match`。`total_matches`、`page`、`has_more` 只描述本地保留结果，远端搜索页使用 `remote_page`/`remote_has_more`，来源覆盖另看 `coverage`/`scan`。本地读完或没有命中，均不证明远端没有发生相关更新。

发图使用条目编号与从 0 开始的图片序号，默认第一张，每次最多三张。`quality=original` 为默认模式：移除常见 CDN `@...` 缩图后缀，下载后保留原始字节，不缩放、不重编码。`quality=preview` 才缩至 1080×1620 范围内并输出不超过 2 MiB 的 JPEG，动图预览发送第一帧。原图超限或发送失败会明确报错，不自动改发缩图。结果中的 `sent_details` 标记实际模式、字节数及是否保留原始字节。

只下载条目已有的 B 站内容图片地址，附带浏览器请求头，不带账号 Cookie，不跟随跳转；原图与预览均有单图下载上限 12 MiB、像素上限 3200 万。只在内存处理，不产生临时下载文件。同一消息的相同参数在本次插件运行期间复用发送结果；部分失败会说明哪张失败，发送结果不确定时停止且不自动重发。图片不作模型识别。

主动生成简报时才复用 AstrBot 模型进行一次逻辑上的挑选与概括。保留兴趣、偏好学习、推荐历史、封面、反馈、撤销和 Markdown 下载。模型格式错误或超时不会自动再调用一次。

## 状态与数据

运行目录为：

```text
data/plugin_data/astrbot_plugin_bilibili_shixun/runtime-direct-v1/
```

不读取或迁移旧版 `runtime/`、`runtime-v2/`。切换账号会等待当前任务结束，并隔离候选、简报、临时搜索和偏好上下文。旧 Cookie 失效后仍可查询已采集内容；UP 和关注新采集需重新扫码，公开关键词搜索仍可匿名使用。

v0.7.0 使用全新插件标识及运行目录，不迁移旧插件的登录和采集数据。重载插件后会记录当前版本、工具数量和名称；初始化失败记录阶段及脱敏代码位置。

凭据位于该目录的 `account/session.json`。POSIX 上账号目录为 0700、凭据文件为 0600；Windows 使用运行账号所在目录的访问权限。备份应包含该目录并按含登录凭据的数据管理，代码分发不携带凭据或数据库。

页面任务沿用稳定请求编号，设置使用版本号校验，断开等待不代表已接受的任务被取消。正常停用插件会等待受跟踪的后台操作结束。

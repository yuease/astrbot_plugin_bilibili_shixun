# v0.8.0：用户隔离

## 已实现

- 按平台适配器、机器人实例 ID 和用户 ID 的可信组合选择独立 Application。用户不能在工具参数中选择身份，管理员聊天也不默认读取其他用户。默认开放普通用户私聊，可配置为仅管理员；群聊保持禁用。
- 登录 Cookie、订阅兴趣、候选池、历史简报、反馈学习、临时结果、任务回执和定时采集均位于各自独立目录。相同 B 站 UID 不合并用户数据。重载后恢复个人调度和重新扫码提醒。
- Dashboard 按登录用户名隔离。管理员可配置 `Dashboard用户名|适配器|机器人实例ID|用户ID` 绑定个人私聊；默认不绑定。查看实际设置的工具返回当前 user_identity，方便确认绑定信息。页面不接受用户选择参数，草稿缓存也按个人 scope key 分隔，账号范围变化时清屏重载。
- 默认最多32个同时启用的个人档案，范围1–128；达到上限拒绝新建，不覆盖已有档案。下调上限后无法恢复的超额档案保留在磁盘，需管理员提高上限后重载。跨用户共用来源请求锁与节流时间，简报模型单并发；各用户自己的任务、投票缓存和账号状态仍独立。
- 固定 SDK 默认按事件循环共享客户端，不能仅依靠不同 Credential 宣称 Cookie 隔离。现在以 ContextVar 为本插件 SDK 请求注入个人 HTTPXClient；匿名搜索与私有采集使用不同 Cookie 会话，其他插件的 SDK 请求继续使用原 resolver，不关闭它们的会话。依赖17.4.2，版本升级需重验这个边界。

## 升级与使用

不迁移旧共享目录。安装 v0.8.0 后，每位用户重新配置自己的长期关键词、兴趣和可选 B 站登录。工具名称及人格启用项沿用 v0.7.0，无需再次改名。GUI 独立档案如需管理私聊内容，必须先配置绑定；页面本身不开放给普通 QQ 用户登录。

新配置为 `allow_private_users`、`max_users`、`dashboard_bindings`。模型配置、访问开关和绑定由服务器管理员统一管理，普通用户不能修改。公开关键词查询无需扫码，UP 和关注来源仍使用自己的凭据。

## 验证范围

99项 Python 回归、5项页面同步检查通过。新增范围包括普通用户设置及撤销隔离、同 UID 的候选/历史/反馈隔离、跨用户条目与搜索任务访问拒绝、登录与真实 SDK HTTP Cookie 会话隔离、匿名客户端、平台实例及适配器隔离、Dashboard 鉴权和显式绑定、参数不能指定其他用户、重载恢复、并发创建复用、档案上限和配置校验。

测试使用独立临时目录与模拟网络/QQ/模型，不调用真实付费模型或保存真实 Cookie。尚未做真实双用户 QQ 扫码、原图投递、Linux全新安装、完整浏览器GUI及负载验收；未扩大 AstrBot 兼容版本范围，未部署服务器或提交市场审核。个人数据处理见根目录 PRIVACY.md。

# B 站直连实现

`main.py` 注册十个聊天工具：设置读取/修改/撤销、订阅启停、匿名临时搜索、统一查询、详情、来源状态、刷新和发图，管理页面 API 和三个 QQ 账号命令。入口先校验私聊权限或 Dashboard 身份，由 UserApplications 按可信宿主身份选择独立 Application；工具参数不能选用户。登录命令不经过模型；初始化后记录版本和工具列表。

## 共享设置

`core/settings_service.py` 是 Bot 与页面的共同设置写入入口，版本使用同一份规范化档案摘要。更新先写持久意图再原子替换文件，重载恢复兼容旧摘要；按请求编号及载荷摘要复用回执。`Runtime.draft` 先经过 Profile 校验，使首次读写的数值和版本保持一致；空设置可读，不要求先保存档案。

Bot 只提供增量关键词、关键词来源开关和兴趣文字修改。兴趣固定为 same_goal，保留学习目标及上下文；页面继续支持显式切换目标。设置历史逐字段记录值及变更头；撤销检查当前版本、字段值与变更头，只恢复目标字段，来源中的关键词开关单独跟踪，不覆盖后续无关修改。只有明确添加长期关键词才允许转入未过期临时缓存。

`Application.lock` 串行化 Bot、页面、账号切换和任务启动。采集、简报或扫码正在进行时拒绝设置写入。页面轮询发现版本变化时自动重填未编辑表单；有草稿时保留旧提交基线、提示显式重新载入，服务端仍校验版本。

## 登录与通知

`services/bilibili_login.py` 通过 B 站网页二维码接口申请二维码，每三秒轮询，最多等待三分钟。从成功响应的 Cookie 取得凭据，并用登录状态接口核对账号。图片仅在内存生成，使用 AstrBot 图片消息发送。

凭据原子写入独立账号目录。页面和模型工具只接收 UID、状态及通知开关，不返回 Cookie、二维码密钥或原始响应。每次主动发送前校验绑定会话仍是获准的 QQ 私聊，退出登录后解绑。OneBot 支持主动推送，QQ 官方适配器使用当前事件被动回复。

登录检查默认每三十分钟一次。只有明确未登录才标记失效，使用账号的来源遇到 SDK -101 响应也触发同样处理；匿名关键词请求不会使账号凭据被标记为失效。限流、超时和风控只作为来源故障。每个失效凭据版本只自动通知一轮；消息无法送达时限速重试，不把群聊或其他管理员作为备用收件人。

## 采集

`services/bilibili_source.py` 对五种来源固定调用 SDK 的搜索、投稿或动态接口，处理签名和设备参数。公开关键词请求显式使用空 Credential，其他来源账号来自本地扫码凭据；工具不能选择 Cookie、任意 URL 或 SDK 方法。

异步网络操作在宿主事件循环执行；解析、SQLite 和领域逻辑在线程执行。来源请求串行并留出请求间隔，整体有时间和页数预算。SDK 可能产生签名、设备初始化或重试等附加请求，因此 source_requests 只统计逻辑来源请求，实际 HTTP 次数保持未知，不报告为零。

JSON 被规范化为既有 Article 和来源贡献。动态保留返回的分页游标与是否还有下一页；转发者和原作者分别署名。关键词和投稿先读取一页，动态最多三批，超出预算明确停止。

`core/attachments.py` 将图片数量和图片解析状态与动态类别分开，规范化投票等附件。动态页缺失的投票选项在采集时按预算补读，失败不丢弃整批内容，缓存按账号隔离。旧记录缺失附件元数据时保持未知，不推断为没有。

`source_scans` 在当前账号命名空间内保存页数、停止原因、分页末尾和观察时间范围。接口成功与覆盖程度分开报告，不按条目数宣称完整；旧数据无扫描记录时覆盖未知。查询输出由 `core/chat_output.py` 精简、统一时区并保留正文片段归属，列表分页与摘要/正文截断分开。

`core/source_diagnostics.py` 对每个来源选择器匹配完整状态列表，不将不存在或停用的来源拓宽为全局查询。逐项区分未配置、停用、未采集、采集失败、有旧内容、快照早于时间窗口及正常可查。`source_scope_status` 与匹配条目分开；部分范围不可用且零命中时返回 partial_scope_no_match。页数只描述保留结果，扫描记录描述有限远端覆盖。

## 临时匿名搜索

`search_bilibili` 使用 SDK 的固定签名搜索接口，一次读取指定远端页的 20 条视频候选，按 pubdate 排序；远端页限 1–3，来源接口超时二十秒，每条消息最多三次不同搜索。搜索与已有任务共用应用互斥和 JobStore；后台任务不随工具等待取消，status 不联网。任务请求摘要、账号范围和回执跨重载保留。

`core/temporary.py` 把证据、临时来源观察与扫描记录写入现有临时表，查询时使用临时来源选择器；当前任务返回仅按该 query_id 取数。临时证据每个账号范围最多 200 条，24 小时清理；任务结果与参数也在过期时清除，保留重复保护指纹。失败写入来源观察，保留旧成功时间和旧内容，后续本地查询仍能报告失败。

临时搜索不创建永久档案、不修改关键词或兴趣、不调用额外模型。用户明确添加同关键词到长期设置后可转入尚未过期的证据，回执区分缓存转入与新采集。未保存档案时使用经过校验的空草稿供本地查询，匿名范围与登录后的账号范围隔离。

## 账号范围与任务

账号 UID 纳入候选命名空间和偏好上下文。登录完成时等待当前任务结束，再切换账号；等待扫码期间拒绝新任务。简报详情和历史只展示当前账号范围。

启用 UP 或关注来源时采集需要有效登录，仅关键词来源可匿名刷新；临时搜索始终匿名。Cookie 失效本身不会删除已采集数据；聊天和已有候选的简报仍可使用，显式退出后不再展示原账号范围。

应用持有运行目录文件锁，跟踪写入、线程及任务。关闭时先停止账号检查和二维码轮询，停止调度并拒绝新操作，再等待在途领域操作结束。SDK 的全局客户端由 SDK 管理，插件不关闭可能被其他插件共享的客户端，也不修改全局日志设置。

## 保留能力

聊天为有界确定性检索，不产生额外筛选模型调用。主动简报通过 AstrBot 的 llm_generate 调用，严格检查 JSON、条目 ID 和数量，再应用偏好排序、保存报告与反馈。页面继续使用官方 bridge 与受限 iframe。

刷新工具 start/status 可有限等待同一个后台任务，默认十秒、上限二十秒，超时不取消采集。`services/refresh.py` 分开报告任务终态和数据覆盖，将实际停止原因汇总为 warnings；任务汇总与原请求回执一起持久化。

`services/images.py` 根据已授权条目解析图片地址，在限额内下载并验证图片，通过当前事件发送图片消息。默认 original 移除已知 CDN 缩图后缀并保留字节；显式 preview 才在线程缩图，不会静默降画质。账户及设置锁阻止发送期间切换数据范围，发送前重新校验当前用户私聊权限。图片只在内存处理；本次运行内相同消息及参数复用发送结果，不确定送达时停止自动重发。

当前使用 runtime-direct-v1，保留 v0.3.x–v0.5.x 登录与数据，不导入 runtime/runtime-v2。已通过 69 项 Python 检查和 4 项页面设置同步逻辑检查；真实匿名搜索读取 20 条候选成功。完整页面交互、真实 B 站投票补读和 QQ 原图收发仍需安装环境确认。

## v0.8.0 用户范围

共享运行目录已停用，用户根目录按可信身份 JSON 的 SHA-256 命名。每个用户独立 Application、Runtime、数据库、登录、调度器和回执；源请求共享 SourceGate，模型共享单并发锁，避免用户增加后无界并发。SDK 默认客户端按事件循环共享 Cookie，因此使用任务上下文分派器为本插件注入独立 HTTPXClient；没有本插件上下文的其他调用继续使用原 SDK 客户端，卸载只关闭本插件创建的会话。每个用户的公开搜索和登录采集还各用一个客户端，防止匿名查询携带账号 Cookie。精确依赖 SDK 17.4.2，不扩大兼容声明。

Dashboard 身份来自官方 request.username，经原鉴权后仅解析 dashboard_bindings 指定的管理员 QQ号或 SID，所有获准页面账号使用同一个已存在的管理员私聊档案；不创建 Dashboard 独立档案，目标缺失、非管理员或歧义均拒绝；无 URL/body 参数可选用户。状态响应包含个人 scope key，页面草稿按该 key 分隔，登录范围变化时清屏重载。旧共享目录不导入。


## 订阅启停

`bilibili_set_subscription_enabled` 对应 `SubscriptionSwitchRequest`，使用和兴趣修改相同的版本检查、持久回执、文件提交恢复及撤销机制。source 为 keyword_search/up/following；UP 只接受已有订阅 UID 并保留其 scope/content_type，关注 UID 由服务端从本人已登录账号注入。工具参数不能选用户、路径、凭据或账号 UID。开启私有来源先检查托管权限及登录，停用不要求登录，不删除内容或自动采集。source_plan 与关键词开关分别记录变更，撤销时保留其他字段。

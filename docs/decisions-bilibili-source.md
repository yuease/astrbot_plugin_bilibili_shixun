# 2026-10-26：全部直连 B 站

用户明确选择：舍弃 RSSHub，降低部署难度；保留 QQ 扫码登录，并在登录失效时发送新二维码。不迁移旧数据，不运行测试，不打包或部署。

决定采用插件内的 B 站直连采集。搜索、UP 主投稿、UP 主动态、关注视频与综合动态均通过 `bilibili-api-python` 的异步只读接口处理，固定到已核对源码的 17.4.2。签名、设备参数和接口参数复用现有库，不在插件内重写签名算法。

网页二维码登录参照 dsh-bili-scroll 的流程独立实现。二维码和轮询状态只保留在内存；登录凭据保存在插件数据目录。Cookie 不通过聊天、模型工具、报告或页面状态返回。

保留管理员私聊、一份账号档案的范围。完成扫码的私聊成为失效提醒的接收者；自动推送支持 OneBot/aiocqhttp，QQ 官方适配器保留手动扫码入口。用户可以退出登录并取消绑定，或关闭自动提醒。

登录状态定期检查；只有明确的未登录响应才判定失效。每次失效只自动发送一轮二维码，二维码本身过期后不连续刷屏。账号切换等待当前任务结束，并按账号隔离候选、简报和偏好上下文。

代价是新增一个 B 站 API 库依赖，并由插件后续跟进接口变动。请求串行并限速；分页、时间与候选预算仍然存在，不承诺完整历史。

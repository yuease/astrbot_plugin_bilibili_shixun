# v0.4.0 问题清单处理记录

依据用户提供的日志问题清单逐项核对当前源码后实施。本次未恢复额外模型筛选。

1. 查询误导与召回：不再注册 query_updates，只注册 search_items。关键词可选，浏览关注更新按来源及时间执行；question 只回显。回归样本中按关注来源和今天返回 9 条，而有意搜索正文“关注”只命中 1 条，明确两种条件的区别。
2. 覆盖度：去掉工具响应中的 insufficient，改为 completeness=unknown/incomplete 及说明。持久化 scan 的页数、停止原因、分页末尾及观察时间；ready 不等同完整。缺失发布时间计数改为明确名称，旧记录没有扫描详情时仍为未知，不按 62 等条数判断全集。
3. 体积：列表不再重复 snippet_evidence、完整来源凭据或 matched_published_at；标题与摘要相同时省略摘要。详情不重复列表摘要，正文去除相同归属的重复内容，同时保留逐段作者、链接和正文位置。9 条模拟文字动态的完整响应小于 7000 字符；真实大小仍随正文、来源数变化。
4. 图片：新增 send_item_images，显式用户要求下按 item_id 和 indices 发图。只处理已保留内容图片，限制域名、路径、下载与输出体积、像素、超时和数量，拒绝重定向，原图不落盘。发送不确定时停止，避免自动补发。图片发送不代表图片已经被模型识别。
5. 时区：查询、详情和来源状态的所有结构化时间转换到请求时区，默认北京时间；今天按该时区的含起点、不含终点窗口筛选。简报输入也统一北京时间。
6. 可观测性：初始化完成记录版本和当前工具列表；失败记录阶段、异常类别及脱敏代码位置，避免输出异常原文、Cookie 或二维码密钥。外部工具插件的“无效名称/未启用”错误不由本插件生成，未修改其他插件。
7. 截断：列表仅用 has_more/next_page 表示后续匹配；单条用 snippet_truncated，详情用 body_truncated，不再返回含义混杂的总 truncated。total_matches 仅计算本地保留且通过当前条件的数据。
8. 工具重叠：两个查询入口合并；来源状态、详情、刷新与发图各有明确职责。更新需重载插件，使宿主重新获取工具定义。
9. 数据归属：工具输出区分 text_dynamic/image_dynamic。省略空正文上下文，保留原作者、原文链接和时间。今天转发旧内容仍可出现在今天查询中，但明确 activity_type=repost，分开显示转发者、转发时间与原文发布时间；逐段归属避免把转发评论算到原作者头上。

继续使用 runtime-direct-v1，兼容 v0.3.x 数据和登录；新增扫描表不重写历史内容。旧 runtime/runtime-v2 仍不导入。用户可在管理员私聊说“刷新一下来源”“今天关注的 UP 更新了什么”“把这条动态的第一张图发给我”。

36 项离线检查与代码、页面语法检查通过。B 站请求、QQ 发送和模型均为模拟，本次未做真实扫码、QQ 收发、付费模型或线上采集。部署环境的网络、B 站限制及 QQ 适配器仍可能导致实际请求失败，届时会返回错误，而不是声称已完成。

# 工具与行为参考

本文补充 [README](../README.md) 的使用指南，描述当前聊天工具和数据边界。工具参数由聊天模型生成，用户通常只需用自然语言表达目标。

## 聊天工具

请在 AstrBot 所用人格中启用需要的工具。插件注册以下十个公开工具：

| 工具 | 用途 |
| --- | --- |
| `bilibili_get_subscriptions_and_preferences` | 读取订阅、兴趣、过滤与采集设置、版本和来源状态。 |
| `bilibili_update_subscriptions_and_preferences` | 增量增删关键词、修改兴趣和关键词来源开关，不覆盖 UP 与关注订阅。 |
| `bilibili_set_subscription_enabled` | 启停关键词来源、已有 UP 订阅或本人关注，切换关注的视频／综合动态范围。 |
| `bilibili_undo_settings_change` | 按变更编号撤销设置修改，防止覆盖后续同字段改动。 |
| `bilibili_search_videos_online` | 匿名临时联网搜索视频，不自动保存为长期订阅。 |
| `bilibili_search_saved_content` | 按来源、时间、关键词及内容特征查询本地保留内容。 |
| `bilibili_read_content_detail` | 读取正文、作者归属、图片列表及已采集附件信息。 |
| `bilibili_get_source_status` | 查看来源可用性、采集时间、扫描范围与停止原因。 |
| `bilibili_refresh_subscriptions` | 开始刷新订阅，或查看当前账号最近一次刷新任务。 |
| `bilibili_send_content_images` | 按条目编号发送图片，默认原图，可显式选择预览。 |

每条消息最多八种不同工具请求，临时联网搜索另限三次。工具不能通过参数指定其他用户、个人档案路径或模型密钥。

## 设置与页面同步

- 修改前先读取当前 `version`。保存需提供预期版本，旧版本提交会被拒绝，避免覆盖新设置。
- 长期关键词最多五个，删除全部关键词会关闭关键词来源。新增关键词保留现有开关，需要采集时应明确开启来源并刷新。
- 兴趣修改沿用已有学习目标和反馈。撤销只恢复目标变更涉及的字段，保留无关后续设置；同字段后来改过时拒绝覆盖。
- Bot 与绑定页面共用设置。页面约每四秒检查更新，未编辑的表单自动载入；正在编辑的草稿保留并提示重新载入。
- 保存设置不会自动采集。登录成功也不会自动开启关注订阅，启停工具不能新增 UP 主，新增 UP 主在页面操作。
- 账号托管权限和页面绑定由插件配置控制，聊天工具及个人订阅页面不能提升权限。

## 临时联网搜索

每次匿名读取按最新发布排序的一页 20 个视频候选，默认远端第 1 页，可显式选择第 1–3 页。默认展示五条，最多十条；关键词命中本身不表示已经验证主题相关性。

默认最多等待十秒，可设 `wait_seconds=0–20`。等待超时不取消后台任务，用 `action=status` 和返回的 `search_id` 查看状态，不重复联网。失败、仍在运行、成功但无匹配分别报告。

结果和临时证据保留 24 小时，每个账号范围最多保留 200 条临时证据。同一消息相同参数复用任务回执。后续可按 `temporary_keyword` 来源查询保留结果，这个来源选择器不会联网；更多远端页需重新调用联网搜索工具。

临时搜索不自动改订阅、不要求先创建长期配置，也不作为自动注入摘要的来源。用户明确将临时关键词加入长期订阅时，可以转入尚未过期的缓存；转入缓存不代表再次联网采集。

## 刷新与数据覆盖

刷新工具 `action=start` 采集已保存且启用的来源，`action=status` 只查询当前账号最近一次采集任务。两种操作默认最多等待十秒，可设 `wait_seconds=0–20`，等待超时不取消任务。

仅启用关键词来源时可匿名刷新；启用 UP 或关注来源则需要获准托管账号并登录。若混合配置含无权使用的登录来源，会明确报错，不静默跳过。关键词与投稿读取一页，动态可在预算内分页。来源请求串行，并受时间、次数和分页上限约束。

- `operation_finished`：任务是否结束，失败时也可为 `true`。
- `operation_succeeded`：这一轮是否保存了可用结果，不表示数据全部取完。
- `data_completeness`：为 `unknown` 或 `incomplete`，触及上限或失败时报告相应限制。
- `warnings`：记录分页上限、预算、分页异常或来源失败等情况。
- `scan`：记录页数、观察到的最早与最新时间、分页停止原因等；来源 `ready` 仅表示接口采集成功。

同一消息重复刷新不会重复执行，采集中的新刷新请求可复用现有任务，任务回执跨重载保存。任务完成不主动向聊天发送完成通知，也不自动生成简报。

## 本地检索

“今天关注的 UP 更新了什么”应明确指定关注来源及今天，不把“关注”“更新”当作正文关键词。有明确主题时再传 `terms`，多个词按 AND 匹配。`question` 用于回显，插件不会另行调用模型推断执行条件。

查询逐项报告所选来源是否存在、停用、未采集、失败、保留旧快照、快照早于请求时段、成功为空或正常可查，部分来源不可用不会静默当成无匹配。

- `total_matches`、`page`、`has_more` 只描述本地保留结果。
- 远端搜索页使用 `remote_page` 和 `remote_has_more`。
- 列表节选截断看 `snippet_truncated`，正文截断看 `body_truncated`。
- 查询时间默认按 `Asia/Shanghai` 返回，可指定 `timezone`。“最近三天”回溯请求时点之前 72 小时，时间范围包含起点、不包含终点。
- 转发时间、原文发布时间、原作者和转发者分别保留，不把今天转发的旧内容当作今天首发。

本地结果读完、无命中或接口分页结束，都不能证明远端全部内容已覆盖。

## 图片与附件

列表包含 `image_count`、`images_status`、`attachment_types`、`has_attachments` 等摘要。寻找图片可用 `has_images=true`，不能只凭动态类型判断有无图片。统计不含视频封面或投票选项图片，数量为零但状态未知时，不能断言原帖无图。

详情保留正文归属 `attributions`，以及图片、投票、视频、专栏、音频、直播、预约、链接和未知附件类型。投票缺失选项在采集时有限补读：每批最多两份，每次最多三秒，计入来源超时；失败不丢弃整批动态。`partial` 或 `unavailable` 表示信息仍不完整，不推断缺失内容。

发送图片需指定条目编号与从 0 开始的图片序号，默认第一张，每次最多三张：

- `quality=original` 为默认模式，移除常见 CDN 缩图后缀，保留下载的原始字节，不缩放或重编码。
- `quality=preview` 缩至 1080×1620 范围内，输出不超过 2 MiB 的 JPEG，动图预览使用第一帧。
- 单图下载上限为 12 MiB，像素上限为 3200 万；超限或原图失败时明确报错，不自动降级为缩图。
- 只读取已采集条目中的 B 站内容图片地址，不带账号 Cookie、不跟随跳转，图片在内存处理。
- 同一消息的相同参数在当前插件运行期间复用发送结果，送达不确定时停止，不自动重发。

图片只用于发送和展示，不做模型识别。QQ 官方适配器返回“已提交”不表示已确认用户收到；链接域名、审核及频控仍需在平台配置中确认。
